### 1.3 라이선스: 전부 참고용으로만

## 2. 제작 기법 (E안 기준)

근거는 동방 메이드의 와인폭스 엘프 GeckoLib 모델(본 225개, 큐브 513개, 회전 큐브 359개, 부풀림 큐브 123개, 거의 전부 면별 UV)을 분석한 것이다. 형태는 가져오지 않고 기법만 쓴다 [확인 데이터].

### 2.1 GeckoLib 4에서 알아 둘 것 [확인: 소스]
- **모든 면을 양면으로 그린다**(뒷면 컬링 없음). 보이지 않는 면은 지워야 비용이 줄고, 평면은 한쪽 면에만 텍스처를 줘야 깜빡이지(z-fighting) 않는다. 음수 크기 큐브로 외곽선을 만들 수 없다.
- `inflate`(부풀림)와 면별 UV를 지원하고, 빠진 면은 아예 만들지 않는다. 박스 UV는 소수 크기를 내림해서 믹셀을 만든다.
- **메시 미지원**: GeckoLib 4는 메시가 없고 GeckoMesh 애드온은 1.21.1 NeoForge 판이 없다. **큐브만 쓴다.**
- 애니메이션 텍스처(`.mcmeta`)로 깜빡임을 하면 발광 마스크와 같이 쓸 수 없고 모든 개체가 동시에 깜빡인다. **깜빡임은 형태(본)로 한다.**

### 2.2 머리와 얼굴
- 머리 큐브 + 얼굴 앞 평면들. E안 기준 얼굴 정면 폭 15텍셀 이상.
- **눈 구조**(와인폭스 기법): 흰자+속눈썹 → 홍채 → 동공과 하이라이트를 겹친 묶음을 얼굴 앞 0.01~0.02유닛에 둔다. 우리 규칙은 눈 평면만 4텍셀/유닛.
- **깜빡임**: 눈 묶음 전체의 높이를 0으로 줄이고, 얼굴에 미리 그려 둔 감은 눈 선이 드러나게 한다. 타이밍은 닫기 약 0.083초 → 유지 0.083초 → 뜨기 0.083초, 7.04초 반복에 2번. 깜빡일 때 눈썹이 살짝 내려간다.
- 동공은 머리 회전을 따라 1텍셀씩 움직인다.
- **표정**: 입·눈썹 그룹을 여러 벌 두고 변수로 고른다. 활성 그룹이 1유닛 앞으로 나오고 기본 입은 숨긴다. 4~6개 표정.
- 일본 CatMaid는 표정 아틀라스를 따로 두고 발광·비발광 얼굴 요소를 나눈다 [확인].

### 2.3 머리카락
- 캡(머리 덮개)은 부풀린 머리 큐브가 아니라 판들로 만든다.
- 앞머리: 큐브 8개를 앞으로 약 −7.5° 기울이고 Z축으로 부채처럼 펼친다.
- 옆머리: 폭 1.02의 가닥(2% 겹침으로 깜빡임 방지).
- 긴 뒷머리: 두께 1유닛 판 2마디 사슬, 양옆 커튼을 ±50° 회전.
- 고개를 들 때 긴 머리가 가슴을 뚫는 문제는 **머리카락을 머리 피치만큼 반대로 돌려서** 막는다(YSM 방식).
- 움직임은 실루엣에 중요한 사슬 몇 개만. 스프링 같은 흔들림은 보조 애니메이션으로 다루고, 충돌을 아는 천 시뮬레이션으로 기대하지 않는다.

### 2.4 몸 (성인만 체형 표현)
- 몸통은 가로 판을 쌓고, 옆 경사면을 ±20° 돌려 허리를 좁힌다.
- 무릎과 팔꿈치에 채움 큐브를 둔다. 정강이 윗면을 평평하게 해서 굽힐 때 뚫지 않게 한다 [커뮤니티].
- **가슴(성인만)**: 큐브 하나, 최대 1유닛 돌출, 옷의 일부로 각도를 준다. 호흡용 가슴 본에 붙이고 **흔들림·물리는 절대 넣지 않는다.** 데이지는 곧은 몸통.
- 성인다움은 적당한 허리선, 팔다리 위치, 옷의 이음새와 갑옷으로 낸다.
- **본 이중화**: 부위를 바깥 본(키프레임용)과 안쪽 본(절차적 움직임용) 쌍으로 감싸서 두 애니메이션이 같은 본을 건드리지 않게 한다.

### 2.5 치마와 옷
- 치마는 다리가 아니라 **허리에 단 패널 고리**, 각 7.5~11° 기울기, 패널마다 2마디 사슬.
- 걸을 때 ±12.5° 흔들림, 앉을 때 옆 패널을 약 −104° 접고 0.8배, 점프할 때 속도에 비례해 들림.
- 다리 관통 대책: GeckoLib에서는 각 패널을 허벅지 회전에 따라 코드로 움직이고 [추정], Epic Fight에서는 치마 끝 가중치를 골반과 허벅지에 50/50으로 나눈다 [추정]. 달리기·앉기·웅크리기·구르기·크게 휘두르기 자세를 따로 확인한다.
- 소매와 코트는 +0.25 부풀림, 갑옷은 어깨·가슴 본에, 리본은 평면.

### 2.6 32px 애니풍 텍스처 [커뮤니티]
- 셀 셰이딩: 기본색, 그림자 2단, 하이라이트 1단, 기본색에서 뽑은 선 색(순수 검정 금지).
- 피부 그림자는 빨강·보라 쪽으로 색조 10~15° 이동, 다른 재질은 단계당 최대 약 20°.
- 흰자는 순백이 아니라 옅은 회청색. 양쪽 눈 같은 자리에 반짝임 하나. 동공은 가운데에서 1px 비켜서 멍한 눈을 피한다. 눈썹 1px 기울기로 감정을 낸다.
- 형태로 외곽선을 만들지 않는다. 원작처럼 두 톤 그림자와 칠한 외곽선을 쓴다.
- Blockbench 텍스처 생성: 해상도 32, "double_use" 체크 해제(아니면 두 부위가 같은 UV를 나눠 씀).
- 실제 셰이더 아래에서 최종 확인한다.

### 2.8 한 캐릭터 제작 순서
0. **레퍼런스 시트 승인**: 실루엣, 16진수 색 램프, 비율, 얼굴 스타일
1. GeckoLib 프로젝트, 면별 UV, 0.5유닛 격자, 4/3 크기. 바닐라 플레이어와 직전 승인 캐릭터를 크기 기준으로
2. 큐브 40개 이하로 블록아웃 → 6방향 실루엣 확인
3. 디테일 전에 본과 피벗: 이중 본, Epic Fight 관절 대응표, 빈 위치 본(`item_r/l`, `back_weapon`, `waist_l/r`). 모든 관절 회전 시험, 무릎·팔꿈치 채움
4. 몸: 몸통 판과 경사면, 가슴 판(성인만), 2.5~3유닛 팔, 정강이 윗면 평평. 약 50~70큐브
5. 얼굴: 머리 큐브, 눈 평면, 홍채, 눈썹·입 평면. 감은 눈 선부터 칠한다
6. 머리카락: 캡 판, 앞머리 5~9가닥, 옆머리 사슬, 2마디 뒷머리, 바보털, 꼬리. 약 40~80큐브
7. 옷: 치마 패널 고리, 소매·코트, 갑옷, 리본, 장신구. 합계 300큐브 이하
8. 정리: 숨은 면 삭제, 같은 평면 겹침 수정, `bbmodel_validate`, 격자 확인
9. 텍스처: 얼굴·표정 영역을 한 귀퉁이에 모아 손으로 배치. 평면색 → 그림자 1 → 그림자 2 → 하이라이트 → 선. 눈은 마지막. 발광 마스크는 마법의 눈이나 후광만
10. 애니메이션 시험: 깜빡임(6.4초 반복, 별도 컨트롤러), 호흡(4초, 가슴), 걷기와 머리카락·치마 따라오기, 앉기, 고개 ±60°, 팔 170°, 다리 차기 90°
11. **검수 루프**: 6방향 렌더 시트 + 얼굴 시트(기본, 깜빡임, 기쁨, 화남, 슬픔, 놀람) + Blockbench 링크 → 사용자 피드백을 티켓 `note`에
12. 내보내기: GeckoLib. 전투 캐릭터는 Epic Fight 메시로 변환(3장). 컷신용 Animated Java 사본은 대상 1.21.1

## 3. 게임 통합

### 3.1 Epic Fight가 플레이어를 그리는 방식 [확인: 1.21.1 소스]
- 플레이어는 Epic Fight 메시 `epicfight:animmodels/entity/biped.json`(슬림 팔은 `biped_slim_arm.json`)으로 그린다. **리소스팩으로 두 파일을 덮어쓸 수 있다.**
- 메시는 12개 이름 붙은 부위를 가져야 한다: `head, torso, leftArm, rightArm, leftLeg, rightLeg, hat, jacket, leftSleeve, rightSleeve, leftPants, rightPants`.
- 기본 메시는 삼각형 472개, 관절 20개(Root, Torso, Chest, Head, 어깨·팔·손·도구·팔꿈치 ×2, 허벅지·다리·무릎 ×2).
- 몸 텍스처는 플레이어 자신의 스킨이다.
- 1인칭은 같은 메시에서 팔과 소매만 그린다. **메시를 바꾸면 1인칭 팔도 자동으로 바뀐다.**
- 메시 JSON에 `cloth_info`(천 물리)를 넣을 수 있지만 커스텀 천을 내보내는 도구는 문서화되지 않았다 [추정].
- Epic Fight 애니메이션은 자체 플레이어 리그 기준이라 **어떤 인간형 개체에도 적용된다.** 다만 우리 비율(골반이 바닐라보다 1.5유닛 높음 등)에서 자연스러운지는 시험이 필요하다 [추정].

### 3.2 주인공을 Epic Fight에 넣는 세 경로 [확인]
| 경로 | 방법 | 판단 |
| --- | --- | --- |
| **A. 우리만의 Epic Fight 메시 (배포용 권장)** | ① Blockbench 큐브 모델 → ② Epic Fight 메시로 변환(공식 Blender 익스포터, Blender 5.0까지 시험됨, 또는 EpicYSM의 MIT 변환 코드를 본뜬 Python 변환기) → ③ 리소스팩으로 `biped.json` 덮어쓰기 + 우리 모드에서 텍스처 강제(안 하면 각자 마인크래프트 스킨이 입혀짐) → ④ 갑옷 레이어 숨김 | 변환기는 새로 만들어야 한다 |
| **B. YSM 2.6.5 + EpicYSM 1.1.3 (빠른 시제품)** | EpicYSM(MIT, 클라이언트 전용, 1.21.1 NeoForge 2026-10-03판)이 읽을 수 있는 YSM 폴더 모델을 불러올 때 Epic Fight 메시로 바꾸고 뼈대 비율을 맞추며 머리카락·치마 물리 사슬(관절 40개 상한)을 붙인다. `/ysm model set <id> - true`로 강제 | YSM이 ARR·네이티브 코어·포맷 변경 중이라 최종판에는 부적합. 버전 고정 필수. 대안 브리지: YSM Epic Fight Compat 1.0.0(MIT, Epic Fight 21.17.3.1 이상 21.18 미만) |
| C. Figura + Figura ExtraFight/Fightura | Figura 아바타 | 비추천: 플레이어마다 따로라 맵이 강제 못 함 |

### 3.3 NPC와 보스
- **GeckoLib 보스는 Epic Fight 무브셋을 쓰면 자기 모델을 유지할 수 없다** [확인: 소스]. Epic Fight 몹 패치에 `"renderer":"epicfight:custom"`을 쓰면 Epic Fight 메시와 뼈대로 그린다. 다만 원래 렌더러의 텍스처를 재사용하므로, **같은 UV로 변환한 메시면 GeckoLib 텍스처를 그대로 쓴다.** 그래서 보스와 전투 NPC는 같은 큐브 모델에서 Epic Fight 메시로 변환한다.
- `epicfight:custom`의 셰이더 텍스처 버그(#1921, 1.20.1에서 보고)는 1.21.1에서 다시 시험해야 한다.
- **비전투 NPC**: 우리 모드의 GeckoLib 4.9.3 개체, 또는 Easy NPC 7.15 + Easy Model Entities 2.5(둘 다 MIT, `.bbmodel`을 바로 읽고 클립 이름으로 재생, 초기 버전).
- **대화 초상화**: VNDialog 1.0.6(MIT, 1.21.1 NeoForge, 약 100만 다운로드). 미연시식 초상화, 분기, 음성, 명령. 이 모드의 `/dialog`는 1.21.6+의 바닐라 명령이 아니다.

### 3.4 컷신 [확인]
- 이야기 캐릭터 컷신은 **같은 개체로 게임 엔진 안에서**: Epic Fight 개체는 `/epicfight animator play <대상> <애니메이션> [전환]`과 일시정지, NPC는 GeckoLib 트리거 애니메이션, 카메라는 Director's Camera.
- Animated Java(1.21.1): 본마다 `item_display` 하나. 큐브는 1.21.1 아이템 모델 회전 규칙을 따르거나 자기 본을 가져야 한다. **텍스처 슬롯 전환은 1.21.4+라서 표정은 변형(variant) 통째 교체로만** 할 수 있다. 기본 대상 버전이 26.2라서 1.21.1로 바꿔야 한다. 주요 캐릭터가 아닌 연출물에만 쓴다.

### 3.5 성능 [확인/추정]
- Epic Fight 기본 플레이어 472삼각형. Sketchfab의 정교한 서브컬처 캐릭터는 3,900~7,100삼각형(약 300~600큐브).
- Epic Fight는 GPU 컴퓨트 셰이더로 메시를 변형하고 Iris 전용 초기화가 있다.
- 보스 + 플레이어 + 몹 4 장면 ≈ 2만 2천 삼각형, 그림자 패스로 두 배. GPU에는 싸다. 위험은 개체별 CPU 작업이라 G6 아레나에서 측정한다.

### 3.6 하나의 원본 모델 → 모든 쓰임
1. **원본**: 캐릭터마다 `models/characters/<id>/` 아래 `.bbmodel` 하나. 면별 UV, 아틀라스 하나, 정수 UV. 본 이름 규칙(`phys_`/`prop_` 접두사)과 큐브마다 Epic Fight 12부위 라벨. 이름 변환표로 Epic Fight 관절, YSM/EpicYSM, Easy Model Entities 이름에 대응.
2. **플레이어**: 스크립트로 Epic Fight 메시 변환(고정 가중치, 비율 맞춘 바이페드 뼈대) → 리소스팩 덮어쓰기 + 모드에서 텍스처 강제. 시제품은 YSM + EpicYSM으로 먼저.
3. **전투 NPC·보스**: 같은 변환기 + Epic Fight 뼈대 + 무브 시트에 맞춘 Blender 애니메이션 + `epicfight_mobpatch`.
4. **이야기 NPC**: GeckoLib 내보내기, 또는 Easy Model Entities + Easy NPC.
5. **컷신**: 같은 개체에 재생 명령 + Director's Camera. Animated Java는 캐릭터가 아닌 연출물만.
6. **초상화**: 고정 카메라 상반신 렌더 위에 덧칠 → VNDialog.
7. **추가할 게이트**: Epic Fight 메시 검사(12부위, 모든 정점 가중치, 관절 40개 이하), 대상별 예산 검사, 레퍼런스와 6방향 실루엣 비교, Iris 셰이더 아래 게임 스크린샷, 보스 아레나 spark 프레임 타임.

## 4. AI가 캐릭터를 만들 때

- **이미지 → 큐브 자동 변환은 블록아웃까지만** [확인]: img2blockbench(MIT)는 큐보이드 20~28개로 실루엣 일치도 0.57~0.68, README가 매끈한 일러스트는 입력으로 안 된다고 밝힌다. BlockSmith는 알파.
- **코드로 3D를 만드는 벤치마크** [확인]: 떠 있는 부품과 조립 실패가 흔하고, 여러 번 고치면 나아진다. 멀티모달 모델은 마인크래프트 스킨을 한 번에 만들지 못한다.
- **AI가 도움이 되는 곳**
  - 턴어라운드(정면·측면·후면) 시트: Seedream 5 [커뮤니티], Nano Banana Pro [확인]가 일관성이 가장 좋다는 근거. Codex 이미지 생성도 후보.
  - 3D 밑그림: TRELLIS.2(MIT, 24GB GPU 필요라 호스팅으로), TripoSR(MIT, 약 6GB). Meshy 무료는 CC BY 4.0, Tripo 무료는 비상업. **Hunyuan3D는 라이선스상 한국 사용 금지.**
  - 재질 견본과 초상화: PixelLab(결과물 소유·상업 사용 가능, 다른 모델 학습 금지). Retro Diffusion은 약관 미확인. 둘 다 큐브 면 UV 배치를 이해하지 못한다.
- **근거에 맞는 순서**: 승인된 턴어라운드 → 본 템플릿 → 결정적 검사 → 턴어라운드와 렌더 비교 반복 → 사용자 검수.
- 커뮤니티 분위기: r/Blockbench는 AI 모델링에 적대적이다 [커뮤니티]. 과제 기록으로서 AI 사용은 숨기지 않는다.
