## 조사 방법

- **조사자 16명**: Claude 서브에이전트 11개(1a 레벨, 1b 전투, 1c 서사·UI·아트, 2a 모델 생태계, 2b 제작 기법, 2c 게임 통합, 3a 시각·사운드, 3b 레벨 디자인, 4a 세부 건축, 4b AI 건축, 5 UI)와 Codex(gpt-6.1-sol) 5회(갈래마다 하나, 중국어·일본어·한국어 자료 담당).
- **검색**: 사용자 Ollama `web_search`/`web_fetch`. Reddit은 Arctic Shift API, 유튜브는 자막 전문, X는 fxtwitter로 우회했다. Bilibili는 HTTP 412로 막혀 영상 설명문만 볼 수 있었다.
- **1차 출처 확인**: Modrinth API를 `game_versions=["1.21.1"]` + `loaders=["neoforge"]`로 함께 걸러 모드 버전을 확인했다. NeoForge·Epic Fight·Kingdom Keys의 1.21.1 브랜치 소스, Epic Fight 21.17.3.1 소스 JAR, Mojang 1.21.1 클라이언트 JAR과 에셋 인덱스를 직접 읽었다. 원작 수치는 데이터마이닝 표와 스팀 업적 통계로 확인했다.
- **직접 시험**: 클라우드에서 1.21.1 구조 파일 쓰기와 GPU 없는 렌더를 시험했다([`tools/build/proto/`](../../tools/build/proto/)).
- **원본 데이터**(검색 결과 JSON, 내려받은 페이지, 소스 클론 약 387MB)는 크기와 제3자 저작물 때문에 커밋하지 않았다. 클라우드 세션이 끝나면 사라진다. 모든 주장은 노트에 URL로 남아 있다.
- **걸러 낸 것**: AI가 쓴 것으로 보이는 사이트(`ludo.guide`, `w12z.com`, `xmodhub`, 일부 2026년 "가이드" 사이트)는 틀린 내용이 섞여 있어 쓰지 않거나 [커뮤니티]로 낮췄다.

## 핵심 결론

### 원작
1. 원작에는 **스태미나가 없다.** 공명율(싱크율) 0~100 하나가 자원이다. 회피는 공짜, 패리는 실패할 때만 깎인다. 1차 조사의 "보스곡 하나 공용"은 틀렸다(세력별 공용 4곡 + 주요 보스 2페이즈 전용곡).
2. M1 구간은 하수도 체크포인트 4개, 빈민가 5개. 지름길 고리, 돌아올 수 없는 낙하로 보스방 진입, 승강기 → 맨홀 → 경치 → 체크포인트로 이어지는 출구 연출을 살린다.
3. 보스 경직 57~88틱, 틱당 회전 상한 6~15°, 예고 동작 최소 10틱 같은 수치를 Epic Fight로 옮길 수 있다. 패리 판정창은 PC에서 프레임 단위로 재야 한다.
4. 원작 비판(비슷한 회색 복도, 지역 사이 검은 로딩, 한국어 글자 배치, 메뉴로만 주문 전환)은 우리가 고칠 점이다. **메뉴를 열면 멈추는 것**은 좋은 평을 받았다.

### 캐릭터 모델링
5. 품질 기준: 공식 YSM 캐릭터 22벌을 측정해 큐브 중앙값 약 593개, 5.5등신, 눈꺼풀·동공·하이라이트 별도 큐브. 우리 예산 제안: 주인공·이야기 NPC 200~450큐브(상한 600), 보스 400~800.
6. 주인공은 **Epic Fight 플레이어 메시(`biped.json`)를 리소스팩으로 덮어쓰는 경로 A**가 최종판, YSM + EpicYSM(경로 B)은 빠른 시제품. 변환기는 새로 만든다.
7. Epic Fight 무브셋을 쓰는 보스는 GeckoLib 모델을 유지할 수 없다. 같은 UV로 Epic Fight 메시를 만들면 텍스처를 그대로 쓴다. 그래서 **원본 `.bbmodel` 하나 → 플레이어·보스·NPC·컷신·초상화**로 나눠 쓴다.
8. 남의 서브컬처 모델은 전부 참고용이다. Sketchfab "NoAI" 표시 모델은 레퍼런스로도 가져오지 않는다.

### 맵 분위기
9. **셰이더 설정은 지역마다 바꿀 수 없다.** 셰이더가 실행 중 읽는 값(동굴 판정 Y, 바이옴 물 색, 바이옴 ID, 차원 설정)으로 지역 분위기를 만든다. 예: Complementary는 카메라가 Y 5 아래면 동굴 모드라서 하수도 바닥을 Y 0 아래에 둔다.
10. Complementary는 수정본을 배포할 수 없어서 설정 프리셋만 함께 낸다. Photon은 수정 배포가 된다.
11. 레벨 규격 초안(복도 3/5/7~9, 아레나 지름 24~56, 체크포인트에서 안개문까지 30초 이내 등)은 PC의 **치수 시험장**에서 재고 계약으로 만든다.

### 세부 건축
12. 연구 결과는 한 방향을 가리킨다: **코드로 짓고(기본 도형 API), 결정적 검사기로 막고, 렌더를 보고 고친다.** 한 번에 통째로 생성하면 실패한다(MineCEraft 엄격 통과율 40% 미만). GDMC 우승자도 집은 손으로 만든 세트를 썼다.
13. 형식은 바닐라 `.nbt`(DataVersion 3955) + git용 SNBT. 1.21.1에는 `/place ... strict`가 없고 GDMC-HTTP 1.21.1판도 없어서 **전용 서버 + RCON**으로 배치한다. NeoForge 1.21.1 다리가 있는 harrynull/mcbuild가 가장 가까운 시제품 후보다.
14. 클라우드에서 deepslate로 8,000블록 구조를 5.9초에 렌더했다. 사용자는 브라우저 structure viewer의 비교 모드로 바뀐 블록을 본다.
15. 장식 모드는 작게: Supplementaries + Amendments, Macaw's 일부, Rechiseled(또는 Chipped), FramedBlocks, 시험 후 Yuushya. 이야기를 지닌 소품(묘목, 흑니, 교회 문양)은 우리 블록으로 만든다. 1.21.1에 없는 블록(창백한 참나무, 송진, 구리 창살 등)과 `minecraft:chain` 이름 같은 함정을 검사기가 막는다.

### 토탈 컨버전 UI
16. NeoForge 21.1.259만으로 HUD 전체를 바꿀 수 있다(이름 붙은 층 25개, `wrapLayer`/`replaceLayer`). Epic Fight HUD는 이름 붙은 층 4개라 ID로 끈다. 리소스팩 코어 셰이더 HUD는 Iris 아래에서 무시되므로 쓰지 않는다.
17. 게임 데이터가 필요한 화면(HUD, 장비, 묘목, 사망)은 Java, 타이틀·설정·로딩 세 단계는 FancyMenu + Drippy(JAR 동봉 불가, 의존성으로만), 그림·글꼴·소리는 모드 안 내장 리소스팩.
18. M1 UI 공수 약 4~6주. 첫 단계는 공명율 시제품과 함께 "데이터와 HUD 경계 증명".

### 출처끼리 엇갈린 것
- **NeoForge 1.21.1 어태치먼트 자동 동기화**: Codex는 1.21.1 문서 페이지를 근거로 "없다", Claude는 1.21.1 브랜치 소스와 changelog(21.1.197 백포트)를 근거로 "있다". 소스 쪽을 따르되 1단계에서 컴파일로 확인한다([UI 문서 2.4](../ui/README.md)).
- Codex UI 보고서는 Sodium 0.8.12 / Iris 1.8.13을 고정 버전처럼 적었는데, Iris 1.8.13은 존재하지 않는다(1차 조사 때 확인, `.ai/debug_protocol.md`). 우리 기준은 `versions.yaml`의 A/B 쌍이다.
- 일본 SOU 폐허 튜토리얼의 "bush"는 1.21.5 블록이다. `dead_bush`나 `fern`으로 바꾼다.

## 다음 단계 (제안)

클라우드에서 바로 할 수 있는 것:
1. **1단계 모드 골격**: NeoForge 1.21.1 Gradle 프로젝트, G1 빌드 게이트, GameTest 골격.
2. **공명율 시제품**: Epic Fight 21.17.3.1 소스를 읽고 적중·피격·스킬 이벤트에 연결. 같이 HUD 층 취소와 공명율 게이지, 어태치먼트 동기화를 확인한다(UI 단계 1).
3. **건축 파이프라인 시험**: 8칸 하수도 한 칸을 구조화 템플릿 방식과 mcbuild 방식으로 만들어 비교. 검사기(블록 상태, 이동 BFS, 지지)와 deepslate 렌더 시트까지.
4. **주인공 레퍼런스 시트**: 실루엣, 색 램프, 핵심 디테일 → 사용자 승인 → 모델링.

사용자 PC가 필요한 것: 위 시험 목록. 1단계 결과물이 나오면 한 번에 묶어서 드린다.
